Task (Asynchronous tasks) "async" and "await"

Cancellation Token:
When something requests cancellation (client disconnect, timeout, app shutdown, etc.), ASP.NET Core marks the CancellationToken as cancelled.
Your code passes that token into async operations, and cancellation-aware operations notice the signal and stop early.

Everythihg shares the same token. If the token is cancelled, all async code that refers to that token can't do anything.
Which is why its in param so you can use it every time you call the token.

NEED "cancellationToken.ThrowIfCancellationRequested();" at the start of your service to check the token status.
Don't need to add for repository layer unless it has a lot of logic.

In short: A cancellationToken is a shared “stop requested” signal passed through async operations so they can exit early cooperatively.

Strategies:
Reactive
- Retry

Proactive

- Rate Limiter = constrains executions to not exceeed a certain rate

Reactive strategy provides access to ShouldHandle which lets you decide whether the

Creating a tool for the LLM to use
Tool uses a weather API to get current data
LLM using a tool = "Function Calling"

The model acts like a router: it reads the prompt, decides a specific function (tool) is needed, and writes out a
	JSON block containing the exact parameters required to run that tool.
When telling the LLM about your tool, you provide a schema declaration
Your application code then captures that JSON, executes the real function, and feeds the results back to the LLM
	so it can write a final human response

The LLM is a project manager that reads a request, decides what tasks are needed, delegates those tasks to the
	engineering team (your application), and then writes a final report for the client (the user). It does not
	access systems or store information itself — all data access and memory are handled by the engineering team.
	
Semantic Kernel does not give the LLM tools — it defines a safe, structured way for your application to
	expose capabilities that the LLM can request.

SMTP (Simple Mail Transfer Protocol) Server
To send an email, I need to connect to a service (smtp) and get a port.
Different ports represent different ways of securing a connection to the server. (Port 587 is most common)
STARTTLS is a security ecryption command so sensitive information isnt readable when traveling through networks.
You need to establish a connection first, then authenticate:
	using var client = new SmtpClient();

	await client.ConnectAsync(
		"smtp.gmail.com",
		587,
		SecureSocketOptions.StartTls);

	await client.AuthenticateAsync(
		"your@gmail.com",
		"your-app-password");

2. You mentioned Clean Architecture. How did you apply it?
	By separating my code into those layers, I maintain a clean folder structure while easily identifying the purpose
	of each layer. For example, the domain layer contains entities, the application later handles the services and
	DTO. The infrastructure layer is the primary connection to the database, which contains all the repositories.
	This means all the code in there, should be accessing the database in some way - read, write and update.
	Using the feature called 'CreateNote' as an example, the domain layer maps the users input into the NoteDomain
	class. It uses the service layer 'CreateNote' to map it into another class called NoteEntity. The service layer
	business logic before accessesing the create function from the infrastructure layer. In the infrastructure,
	it creates the entity in the database and the process is done. Each layer gains access to another layer using
	Dependency Injection. 
	- Clean architecture
	- SOLID principle
	- DDD 

3. Walk me through the Azure Table Storage migration and how you redesigned the data model.
	The migration to Azure Table Storage only required change in the infrastructure layer since we're only changing
	the database. Unlike SQL, the Table Storage structure uses Partition and Row keys as the two main identifiers
	when search through the table. Instead of using and ID, I used a GUID, otherwise it would have to perform a
	search for existing IDs which complicates things, defeating the purpose of table storage. The reason for
	switching to table storage is to enhance search efficiency. However, table storage is mostly used for read,
	so when developing the write operations like 'Create' and 'Update', it contained a few extra steps compared to
	SQL. In SQL, update was simple however in Table Storage, each parameter had to be updated manually, including
	those that did not change. The Partition key I used is the user email, then the GUID for the Row key. These two
	keys help narrow the to the least amount of matches, making the search time quick. 
	- Table Storage parttion strategy
	- Table Storage transation and batch
